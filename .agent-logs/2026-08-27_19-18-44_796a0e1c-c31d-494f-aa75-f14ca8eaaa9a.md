Test failure is reproducible, not a flake. Located it: `ws.test.ts` `afterAll`.

**Cause.** `app.close()` terminates sockets but does not wait for the per-connection `sendChain`. An `appendMessage` transaction holding `SELECT ... FOR UPDATE` on collaboration Y is still open when the cleanup `DELETE FROM users` starts. The cascade locks collaboration X for deletion; the in-flight insert into `messages` needs an FK share lock on X and waits; the delete waits on Y. Mutual wait, deadlock. `Bun.sleep(150)` is a race, not a fix.

The honest fix is server-side, not test-side: shutdown should finish committing messages it already accepted. `registerMessageSocket` tracks open sockets already; it should also track each connection's `sendChain` and `await Promise.allSettled(...)` in the `onClose` hook before returning.

## Design: SSE status stream

Bounded change. Reuses the broker, the guard scopes, and the `/bff` proxy that already exist.

**Contract** (`packages/contracts/src/events.ts`, new)

```ts
CollabChanged = { t: 'collab_changed', collaborationId, reference,
                  from: CollabState, to: CollabState, actor: Actor,
                  feeMinor, counterFeeMinor, allowed: CollabEvent[], updatedAt }
```

One frame type, plus a `hello` on connect carrying the protocol version. No counters, per your call.

**Broker goes generic.** `Broker<T>` and `InProcessBroker<T>`, defaulting to nothing. `ws.ts` takes `Broker<Message>`, the stream takes `Broker<CollabChanged>`. Same file, no new abstraction, and Redis later swaps both at once.

**Rooms are `brand:<brandId>` and `creator:<creatorId>`.** A transition publishes to both, so each side gets its own frame with its own `allowed` array, computed by `allowedEvents` exactly like `GET /collaborations` does. An SSE connection subscribes to one room, which means a collaboration created after connect is covered without resubscribing.

**Endpoint is `GET /{side}/events`**, registered inside the existing guarded scope, so it authenticates by cookie through `requireRole` with no new auth path. `reply.hijack()`, then raw writes: `retry: 3000`, a `: ping` comment every 25s, and `event: collab_changed` frames. Open streams block `app.close()` the same way sockets do, so the same `onClose` hook ends them.

**Publish site is `collab-routes.ts`**, after the transaction commits. Invite publishes too, so a new offer appears without a refresh.

**Web side** is `useCollabEvents(side)` opening an `EventSource` on `/bff/{side}/events`, calling `router.refresh()` on each frame, debounced 200ms. Server components already fetch the rows, so refresh is the whole update path. No second copy of collaboration state on the client.

**One risk I will verify before building on it:** whether the Next rewrite streams SSE or buffers it. If it buffers, the fallback is the ticket already in `ticket.ts`, issued user-scoped instead of collaboration-scoped, with `EventSource` pointed straight at the API. I will curl the proxy first and tell you which one we got.
